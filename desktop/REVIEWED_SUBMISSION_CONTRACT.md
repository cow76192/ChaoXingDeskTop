# 人工副本独立提交：第二期合同草案

状态：**待实现与单独审查**。2026-10-24。当前只提供零网络编辑、校验、保存、复制和导出；没有“提交副本”的 GUI 或 worker action。

## 已落实的第一期边界

- 编辑副本和生产 `discussions/`、`activities/` 完全分离。副本保存不会改变原草稿、提交策略、任务状态或防重记录。
- 来源是当前有界结果模型中的本地草稿完整快照，以 SHA256 绑定；问卷明确 `submit_status=draft` 的未完整草稿也可修正。记录更新、切账号、任务运行、停止／异常退出或来源淘汰后只读。重启后保存的副本可读取／导出，必须重新确认来源才可继续编辑。
- 问卷按原生题目／选项 ID 编辑，复用 `validate_answer`。缺题、重复、未知选项、选择数量、文本长度、未适配题型都给出错误。允许保存待修正副本，但这不代表提交资格。
- 讨论本地仅检查非空、1000 字符上限和控制字符；平台最低字数等未出现在 UI 事件中，不能推断为零限制。
- 副本来源是脱敏且有长度上限的显示快照，**不能直接作为平台提交 payload**。第二期必须证明它与重新取得的原始平台结构一致。

## 第二期必须满足的合同

1. 用户明确选择单条副本，展示完整人工内容、当前账号／课程／目标和一次发送边界。审核快照包含副本版本、来源摘要和当前会话修订；确认期间发生变化必须失效。
2. 专门的 worker action，仅使用已读课的 Cookie 会话、明确 UID 和当前课程身份；不调用整轮 runner、不生成内容、不回退密码、不追加学习次数、不触发其他任务。
3. 只读取得当前课程、章节卡片和原生目标；拒绝使用磁盘旧签名或旧表单。逐项确认 UID、课程、班级、话题／单位空间、原生 ID、标题／正文／完整题目／选项／限制、当前本人参与状态和写入资格。变化时保留副本，零写入。
4. 在现有原生目标的进程间锁内加载生产记录。`intent`、`unknown`、已发布／已参与、平台拒绝和损坏记录均不得通过副本版本、重启、切策略或删除显示绕过去重。本人状态未知不发送。
5. 讨论需要为人工来源设计向后兼容的持久格式。不得将改写后的内容继续标成 AI 或固定“好”。活动同样需要在答案来源契约中明确人工来源。旧版本遇到新格式应拒绝写入并保留原件，不能自动降级。
6. 整份内容校验通过后，先原子持久化意图，再用禁止重试及重定向的独立 transport 最多发送一次。意图保存失败零发送；意图之后的取消、超时、异常退出均按未知保留，不能自动解锁。
7. 发送后只读回查本人内容／参与证据。讨论必须核对精确人工正文；问卷必须区分参与证据与答案内容是否可读回。提交确认、任务点、章节完成与成绩分开，不能以成功 HTTP 响应代替证据。
8. 当前“只读核验”不调用活动完成回调。若第二期需要该回调，须明确它是独立写入、补单次意图与异常恢复合同后再接入，不能混入只读路径。

## 专用离线矩阵（第二期接入口前须补齐）

| 注入点 | 必须观察到的结果 |
| --- | --- |
| 双击、两个进程、相同目标不同副本 | 共享原生目标锁和生产意图，最多一次发送 |
| UID／Cookie／课程／题目／约束变化 | 保留副本，零生成、零发送 |
| 本人已参与、分页证据不足、登录页、HTTP 200 业务失败 | 拒绝发送，不把查询失败解释为未提交 |
| 意图写失败、磁盘满、外部修改、损坏记录 | 原件保留，零发送 |
| 意图保存后、发送中、读回前崩溃或取消 | 重启只读核验，不能强制重发 |
| 明确拒绝、响应丢失、读回未定、读回内容不符 | 不改成成功，不重试写请求 |
| 读回成功后本地更新失败 | 原意图仍阻止重发，界面说明证据与本地记录差异 |

既有 `test_discussion.py`、`test_activity.py` 覆盖原 runner 的单次发送和未知意图；它们不能代替上述新 action 的专用验收。当前第一期新增测试也不宣称第二期已实现。此分期是实现依赖边界，不是要求用户重新授权整个开发任务。
