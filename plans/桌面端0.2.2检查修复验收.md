# 桌面端 0.2.2 项目检查与修复

日期：2026-10-13。

检查范围：desktop 的配置、答题路由、Qt 界面、worker 调度、vendor 平台协议适配层、依赖环境和 Windows 打包流程。reference/chaoxing 保留作为上游参考。当前项目根目录没有 Git 仓库。

## 已确认并修复的问题

| 问题 | 原行为与影响 | 修复 |
| --- | --- | --- |
| 多个题库 Token 过滤不完整 | 新配置中的 yanxi_tokens、like_tokens 只按完整字符串过滤；服务只记录其中一个 Token 时可能泄露 | 拆分所有 tokens / *_tokens 字段，按长度从长到短逐个过滤 |
| HTTP 会话重复创建 | SessionManager 每次取用都会执行初始化；32 次并发取用创建了 32 个 Session，连接池被反复替换 | 加锁创建单例，并在发布实例前完成一次初始化 |
| 选择题选项在表单阶段被改写 | A 为“上海市”、B 为“上海”时，已选择 B 的答案被子序列匹配改成 A；重复选项文本也会失去原编号 | 路由保存已核验的选项编号，表单直接使用编号；每轮查询清除旧编号，随机补全同样保留编号 |
| 真实页面丢失选项图片 | 选项仅提取 aria-label 或纯文本；图片题可能被误当作纯文本题交给 AI | 保留真实选项中的 img，包括有 aria-label 的选项；图片预览和 AI 视觉限制继续使用现有流程 |
| 选择题内容解析错误 | DNA 等全大写选项内容被误当作多个选项编号；带图片的相似文本缺少图片身份核验 | 优先匹配完整选项内容，核对图片 URL，歧义答案保持待处理；显式字母编号保留原选择 |
| 布尔值大小写处理不一致 | 校验接受 TRUE，部分服务运行时却只识别 true，AI 凭据校验也会被跳过 | 所有已知布尔配置进入 worker 前统一小写；校验 AI 启用状态时也忽略大小写 |
| 判断题自定义规则空格 | 逗号分隔规则的前后空格影响识别 | 去除规则两端空格并忽略空项 |

## 复现命令

在项目根目录执行：

```powershell
Push-Location desktop
.venv/Scripts/python.exe -m unittest discover -s tests -p 'test_*.py'
.venv/Scripts/python.exe tests/gui_smoke.py build/audit-gui
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe -m PyInstaller --noconfirm ChaoxingDesktop.spec
Pop-Location
desktop/.venv/Scripts/python.exe desktop/tests/release_smoke.py desktop/dist/ChaoxingDesktop plans/audit-0.2.2/release-smoke
desktop/.venv/Scripts/python.exe desktop/scripts/package_release.py
```

本次仅执行离线演示和模拟接口测试，没有登录真实账号、运行真实课程、发送外部通知或调用付费题库 / AI。真实平台接口、验证码、图片下载和第三方服务的实际可用性仍需对应环境验证。
